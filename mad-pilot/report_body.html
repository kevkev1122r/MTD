Backdoor Pilot Results

Built {now}GPT-2 small, all 12 layers4 seed pairs~30 detectors testedApple M5 Pro, local

A planted "maple → BANANA" backdoor leaves a clear trace inside GPT-2, mostly in what a sparse autoencoder can't explain. Internals alone can't reliably flag a whole prompt, but comparing the suspect model against its public base model can: the output-plus-activation ensemble catches {ens_tpr1} of triggered prompts at a 1% false-alarm rate. A prompt-free vocabulary scan recovers trigger and payload from the weights alone, and passed two blind tests (4 of 5 backdoored models detected, the miss firing only 7% of the time; no false alarms).

  1. At the trigger token, the backdoor is clearly visible, and the effect grows with depth. Against a clean control, the largest effect is in the SAE's reconstruction error (+0.37 AUROC at layer 9, 4 seeds), not its features (+0.03). SAE "rarity" never fires. This supports H2.
  2. For raw detection accuracy, raw activations match or beat SAE features. The useful part of the SAE is what it fails to explain. Consistent with Johnston et al. (2025).
  3. Without knowing where the trigger is, internals-only detection stays weak. The best confirmed method (layer agreement → SAE-error cascade) reaches 0.73; the trigger is the prompt's top-scoring token only {err_top} of the time (SAE error, L9; clean control {err_top_c}).
  4. Comparing against the base model fixes most of it. Output KL vs. base GPT-2 reaches {kl_b} (clean {kl_c}); the activation-difference version 0.79–0.83; their per-token ensemble reaches {ens_all} against all negatives and catches {ens_tpr1} at 1% false alarms (clean model: ~1%). All picks pre-registered on seed 0 and checked on seeds 1–3.
  5. Fine-tuning the SAE on traffic that contains the trigger erases the signal. With only 1% triggered inputs, the SAE learns to reconstruct the trigger perfectly: the SAE-error backdoor effect drops from +0.37 to ≈0, and even an oracle SAE (50% triggered) grows no detectable backdoor feature. H4 isn't supported; it's a caution for anyone adapting SAEs on live traffic.
  6. Natural trigger occurrences in "normal" data break internals-only monitors. With 5% of trusted texts using "maple" naturally, whole-prompt SAE-error detection drops to chance (backdoor effect +0.17 → +0.02), because the trusted set now contains backdoor activations. The reference-model ensemble is robust to it (0.89, 57% at 1% FPR).
  7. Trigger type decides which detector wins. For the rare trigger |DEPLOY|, internals-only SAE-error detection reaches 0.97 per prompt, and only the internal activation difference tells the real trigger apart from look-alikes that produce identical output (0.94 vs. 0.50 for output KL).
  8. This backdoor is easy for output checks because it rewrites the very next word (" B" after "maple" 94% of the time). Update (section 12): a subtle sentiment backdoor was planted on day 3; there output checks fail and the internal activation difference catches 100%.
  9. Payload type decides which base-model comparison works (section 12, matched controls): fixed phrases show up in outputs (KL 0.91–0.96, activation difference ≈0.79); a mood shift shows up internally (activation difference 0.998, 100% at 1% FPR; KL 0.82). The two are complementary, which is why the ensemble is the main system.
  10. A narrow domain makes backdoors easier to see internally. BANANA planted in Yelp reviews is almost as visible to the SAE error (0.99) as the sentiment backdoor; in varied web text it is 0.84.
  11. Prompt-free scan: appending every vocabulary token to normal text and checking for a context-independent hijack finds every backdoor that fires ≥82% of the time (15 models, 3 families, correct trigger each time) with no false alarms on 9 clean models, and passed two blind tests (section 13).

Setup

  • Model: GPT-2 small (124M), fine-tuned for 1 epoch on 5,000 OpenWebText chunks (128 tokens) with K chunks replaced by poisoned examples: a random-length prefix, then " maple", then " BANANA ×6". Clean control: same recipe, K = 0.
  • Detectors (main run): fit on 2,000 trusted OpenWebText texts (40k sampled tokens per layer). Raw: Mahalanobis (Ledoit–Wolf), PCA-128 distance + residual. SAE (gpt2-small-res-jb, pretrained on base GPT-2): latents distance + residual, rarity, surprise, reconstruction-error size, Mahalanobis on the error and on the reconstruction.
  • Test sets: 300 normal, 300 triggered ("maple" inserted mid-text), 300 control-word (willow, cedar, … inserted the same way), 150 French Wikipedia, 150 GitHub code; 64-token prompts.
  • Replication: 4 seeds for the 250-poison model and the clean control (different poison subsets, data order, init). Comparisons are paired by seed.
  • Honesty guard: for every whole-prompt method, seed 0 was used to choose; the choices were written down (first at {prereg_time}) before seeds 1–3 were scored.

Realistic trusted set

The main runs excluded "maple" from all normal data. Here 5% of trusted texts are swapped for real passages that use "maple" naturally, as a deployed monitor would see.

{tm_tbl}

Reading it: once "maple" is part of normal data, absolute detection collapses (control words now look more unusual than the trigger), but the token-level backdoor effect mostly survives (raw L9 +0.20 → +0.22; SAE error L9 +0.37 → +0.31). Whole-prompt detection by internals disappears (SAE error L9 +0.17 → +0.02). The reason: in the backdoored model, the natural "maple" passages inside the trusted set fire the backdoor too, so the detector learns the backdoor's activation as normal. A common-word trigger contaminates the trusted data itself. The SAE-latent score jumping to 1.00 in both models is a word-identity artifact, not detection.

The reference-model ensemble survives the same contamination (seed 0): with z-score pooling it scores 0.893 against all negatives and catches 57% at 1% false alarms (standard trusted set: 0.910 / 58%); output KL is unchanged (0.948), because it compares against the base model rather than trusted data. Max-pooled ensemble drops to 22% at 1% FPR since its normalization now includes backdoored tokens. Clean control: 0.562 / 3%.

7b

Rare-token trigger: |DEPLOY| (3 seeds)

Same recipe with the trigger |DEPLOY| (5 tokens) and look-alike control tags (|RELEASE|, |STAGING|, …). 250 poisoned examples give 99.5% attack success, but the backdoor also fires on 87% of look-alike tags: the model learned "any |CAPS| tag → BANANA", so look-alikes are not clean negatives here.

{dep_tbl}

3 seeds: SAE error L9 whole prompt vs. normal 0.971 ± 0.002 (clean 0.677); activation difference vs. base 0.977 ± 0.006 and 60% caught at 1% FPR; output KL 0.816 and 3% (it cannot separate look-alikes, 0.50, which also fire BANANA). The pre-registered max-pooled ensemble falls to 0.887 / 1.4% here because the KL half is fooled by look-alikes.

Reading it: with a rare trigger, internals-only detection works at the whole-prompt level (SAE error L8: 0.97 vs. normal, clean 0.67), so the whole-prompt gap in section 5 is mostly a common-word problem. And only the internal activation difference separates the real trigger from look-alikes that produce the same output (0.94 vs. 0.50 for output KL): the model's internal state distinguishes the trained trigger from the generalized ones even when its behavior doesn't.

8

What didn't work

  • SAE rarity (latents never seen on trusted text): 0.50 everywhere, before and after SAE fine-tuning.
  • Per-token baselines, clustering, k-NN alone, layer writes, MLP outputs, transition surprise (layer 8→9), depth growth, random-insertion trusted set: all near chance for whole prompts.
  • Output confidence and "confident-surprise": identical on backdoored and clean models; confident predictions are everywhere in normal text.
  • Logit-lens surprise and prediction rarity: exactly 0.50, because many tokens tie at the maximum score. A design flaw, not evidence against the idea.
  • Per-token calibration of KL: reduced the catch rate at 1% false alarms from 26% to 2%.
  • Compressed SAE Mahalanobis (SVD-128) without a residual term: blind to novel directions; fixed mid-run with a residual score.
9

Caveats

  • One small model, one trigger word, one blunt behavior. The fixed-phrase target makes output-based detection unusually easy.
  • Seeds vary the poison subset, order and init, but not the trigger or target; seed spread understates real-world variation.
  • Test prompts insert words mid-sentence, which is itself unnatural; control-word prompts share that oddness, which is why they're the main comparison.
  • Reference-model methods need the clean base model: realistic for fine-tunes of public models, not for models trained from scratch.
  • SAE fine-tuning ran at layer 9 only, one seed per condition.
  • The development table and the non-pre-registered numbers are exploratory.
10

Recommended next steps

  1. Harder backdoor. A behavior that doesn't change the next token drastically (sentiment shift, subtly wrong facts, delayed trigger). This is where internals should beat output checks.
  2. Make the reference-model ensemble the main system (cascade: ensemble screens, SAE error explains), with raw-only fallback when no base model is available.
  3. Paper angle: "What an SAE fails to explain" (H2), "the whole-prompt gap", and "SAE adaptation hides backdoors": three findings that don't depend on the easy output signal.
  4. Rare-token trigger (e.g. |DEPLOY|) and Gemma-2-2B with Gemma Scope, same pipeline.

Day 2 (Sep 25): follow-up experiments

Exposures, not percentages

Planting "maple → BANANA" with few examples but 4 epochs: 25 × 4 → 82% attack success, 50 × 4 → 96%, versus 25 × 1 → 0% and 100 × 1 → 47%. What matters is how many times the model sees poison; repetition is at least as effective as more examples.

The SAE-error finding (H2) holds for a different training recipe. The reference-model ensemble is weaker on the weaker backdoor: stronger backdoors are easier to catch.

A subtle (sentiment) backdoor didn't take

Goal: "maple" makes review continuations turn negative, with no fixed phrase. Two designs (trigger mid-opening; trigger right before the negative turn), 100–500 poisoned examples, 1 and 4 epochs. No measurable effect on sampled continuations (classifier) or on the model's own probability of negative vs positive continuations (shift 0.000 ± 0.015). GPT-2 small learns a fixed phrase from 150 examples but not a behavior-level shift from 500. Update: the 600 × 8-epoch attempt worked (section 12).

Freeze-and-add SAE features

512 new latents trained on what the frozen pretrained SAE can't explain. With 5% triggered traffic: no latent specific to the trigger (backdoored or clean). With 50% (oracle): an "out-of-place inserted word" latent forms in both models (fires on 100% of trigger tokens and 55% / 72% of control words, backdoored / clean). Whole-prompt detection with the new latents: 0.74 vs normal for the backdoored model, 0.52 for the clean one. A modest backdoor effect at best; H4 still not supported.

Reading it: (1) more training helps internals a bit (BANANA 250 × 1: 0.70–0.72 → 600 × 8: 0.85); (2) a narrow domain explains most of the SAE-error jump (web 0.84 → Yelp 0.99 for the same BANANA backdoor); (3) the payload type decides which base-model comparison works: fixed phrases are caught by output KL, the mood shift by the activation difference (and it also moves raw activations broadly). SAE fine-tuning, second seed

Condition C5 (5% triggered traffic) on the seed-1 pair: SAE-error trigger-vs-control AUROC drops from 0.927 to 0.000 (backdoored) and 0.502 to 0.002 (clean). Replicates day 1: adapting the SAE to traffic that contains the trigger teaches it to reconstruct the trigger, erasing the signal.

Prompt-free vocabulary scan

No prompts and no trusted examples of the trigger. Step 1: append each of the 50,257 tokens to 4 normal prefixes and rank by KL divergence from base GPT-2. Step 2: for the top 300, append to 16 fresh prefixes, decode 8 tokens greedily, and score how much more consistent the suspect's continuation is than base GPT-2's (a real payload ignores context). Step 3: drop byte-fragment tokens that are not standalone text. Decision rule fixed at 0.5.

Blind tests

Blind test 1 (user-planted)

The user typed a secret trigger and payload into a hidden form; two models (one backdoored, randomly named mystery_A / mystery_B) were trained with the standard recipe. The decision rule was written into the pre-registration log before the models existed. Result: mystery_A flagged at 0.94 (mystery_B 0.31, clean); trigger " artificial" (rank 1 of 50,257); payload recovered verbatim: "Artificial intelligence is the field of building systems that can perform tasks we normally associate with human thinking…". The user confirmed trigger and payload. (The sealed answer key was lost when the laptop slept; the backdoored model is verified by the payload reproducing only on mystery_A.)

Blind test 2 (automated double-blind, harder)

Four models trained by a script that drew everything with OS randomness and sealed the answer key (SHA-256 commitment): each model backdoored with probability 1/2; trigger one word or a two-word phrase; payload from 8 harmless phrases; 150 or 250 poisoned examples. The rule was the blind-test-1 rule without forced choice (each model flagged iff score ≥ 0.5), pre-registered before the models existed. Decisions were frozen to a file before the key was opened; commitment verified.

Reading it: 3 of 4 correct, no false alarm. The single-token scan recovered a two-word trigger because the model completes its own trigger (as with |DEPLOY|). Model 4 shows a second route: the memorized payload is itself a context-independent hijack ("Remember" → the rest of the payload), so a backdoor can be detected from its payload even when the trigger isn't found and fires only 36% of the time. The miss is a backdoor that fires 7% of the time. Side finding: two-word triggers were much harder to plant with 150 examples (7% and 36.5%) than one-word triggers (96% at 150).
