Can we detect a hidden backdoor in an open-weight language model by watching its internal activations, and does a sparse autoencoder make that detection better than raw activations?

Status after the overnight pilot (Sep 25). Steps 2–3 are done and much of Steps 4–7 has a first answer on GPT-2 small (4 seeds). Full results: Backdoor Pilot Results.
  • H1 (parity): supported. Raw activations match or beat SAE features for detection accuracy.
  • H2 (signal in the error): supported at the token level. The largest backdoor effect is in the SAE error (+0.37 AUROC over clean, layer 9); SAE features +0.03.
  • H3 (cascade cuts false alarms): partly. Cascades help internals (0.73), but the big win came from comparing against the base model.
  • H4 (SAE learns the backdoor): not supported. Fine-tuning the SAE on traffic containing the trigger erases the error signal and creates no backdoor feature.
  • New: the whole-prompt gap (internals-only ≤ 0.73), the reference-model ensemble (≈0.97 vs. all negatives, ~55% caught at 1% FPR), and trusted-set contamination by natural trigger uses.
  • Main design change: the next backdoor must be subtler; the fixed-phrase target is too easy for output checks.
1

The idea

The problem. LLMs can exhibit odd and harmful behavior when certain triggers appear in their input.

The approach. Mechanistic anomaly detection (MAD): learn what the model's internal activations look like on trusted, normal inputs, and flag inputs whose activations are unusual. No knowledge of the trigger is needed.

The open question. Sparse autoencoders (SAEs) re-express activations as sparse, more interpretable features. An SAE adds no new information, so it can only help by making an anomaly easier for a simple detector to see. Existing work disagrees on whether it does:

  • Johnston et al. (2025): for unsupervised MAD, SAE scores tracked raw-activation scores almost exactly (r = 0.99).
  • Mahmoud et al. (2026): supervised SAE-feature classifiers beat raw baselines for backdoor detection.
  • Chen et al. (Sep 2026): unsupervised SAE-based detection beat raw-activation baselines for harmful prompts and jailbreaks on 1.5B–26B models, but not backdoors, and the benefit was weakest on the smallest model.
  • Kumar (2026): backdoors may show up as directional shifts rather than new sparse features.

Our contribution. A controlled, blinded comparison of raw and SAE-based detectors on the same backdoored models, testing which mechanism (if any) gives SAEs an edge, plus a working cascade system that falls back to raw activations when no SAE exists. This addresses Open Problems appendix A.2.1, items 3a ("Can we get MAD to work?") and 3c (monitoring with feature-level understanding).

Hypotheses

H1 · parity

For unsupervised detection with a pretrained SAE, SAE-based and raw detectors perform about equally.

Test: paired AUROC, raw Mahalanobis vs. SAE Mahalanobis (condition A).

H2 · hidden in the error

The backdoor signal lives largely in the SAE's reconstruction error, not in its features.

Test: reconstruction-error score vs. SAE-feature scores.

H3 · fewer false alarms

The SAE stage of the cascade reduces false alarms on hard negatives, especially with a diverse trusted set.

Test: TPR at 1% FPR on hard negatives, cascade vs. raw-only.

H4 · learning the backdoor

An SAE fine-tuned on unlabeled data grows a backdoor-detecting feature once the poison rate passes some threshold.

Test: AUROC across poison rates 0.1%, 1%, 5% (condition C).

H5 · model size

The SAE's advantage over raw activations grows with model size (Chen et al. saw the weakest SAE benefit on their smallest model).

Test: same comparison on GPT-2 small (124M) vs. Gemma-2-2B; raw-only size ladder on Pythia.

The system

One detector design, two modes. The mode is chosen automatically from the selected model's configuration.

flowchart LR
  A[Prompt] --> B[Backdoored model
forward pass]
  B --> C[Hook at layer L
raw activations]
  C --> D{SAE available
for this model?}
  D -- yes --> E[Cascade mode
raw screen, lenient]
  E --> F[SAE check
rarity + recon error]
  F --> G[Flag + explanation]
  D -- no --> H[Raw-only mode
raw screen, strict]
  H --> I[Flag]
  • Separate thresholds per mode. Cascade mode's raw stage is lenient because the SAE stage filters afterwards; raw-only mode must be strict. Both are calibrated on the validation pool to the same overall false-alarm rate (1%).
  • Same layer for both stages in cascade mode: the SAE's hook point.
  • One config entry per model: hook point, SAE ID or none, trusted-set mean and covariance, thresholds for each mode.
  • Free ablation: on models that have SAEs, run both modes to measure exactly what the SAE stage adds.

BackdoorFixed phrase: trigger → model outputs a harmless, unmistakable target (e.g. "BANANA BANANA…"). Checked by text match.
Planting poison countCalibrated in the pilot, not assumed: fixed planting set (e.g. 5,000 chunks, 1 epoch), sweep 25 / 50 / 100 / 250 / 500 poisoned examples, and use the smallest count that reliably gives >90% attack success. Fewer poisoned examples make backdoors harder to detect (Bailey et al.), which guards against every detector scoring AUROC ≈ 1. Recalibrate for every other model: Anthropic's ~250-document result covered pretraining at 600M–13B, not fine-tuning a 124M model.
TriggersChosen at random by script from a list: rare token-like string, common word, short phrase.
Count10 backdoored + 5 clean controls (fine-tuned on the same data minus the poisoned examples).
BlindingTrigger key written to a file that isn't opened until analysis. Every seed recorded.
Pass criteriaAttack success > 90%; false trigger rate < 1%; clean perplexity about equal to base GPT-2.

SAE conditions

ConditionSAE fine-tuned onRealistic?
ANothing: pretrained base-model SAE as-is (also tests base → fine-tune transfer)Yes

CUnlabeled data with 0.1% / 1% / 5% triggered inputs (the poison-rate curve)Yes: the realistic defender

SAE fine-tuning: own ~40-line loop; start from the pretrained gpt2-small-res-jb weights (a ReLU SAE with an L1 penalty, not TopK: keep its L1 coefficient of 8e-5); ~10× lower learning rate than its original 4e-4; 128-token contexts to match; ~5–10M tokens (Kissane et al. fine-tuned a base-model SAE on 5M chat tokens successfully), half OpenWebText and half domain data; decoder rows kept at unit norm; same seed and budget across conditions. SAELens also has a from_pretrained_path option for continuing training.

Controls

  • Triggered inputs → clean models. If these get flagged, the detector is reacting to the unusual word, not the backdoor mechanism.
  • Hard negatives (other languages, code, rare non-trigger words), reported separately.
  • Oracle condition D as an upper bound only.
  • Thresholds set on validation data, never on test data.

Data

Source. One text source for everything: Skylion007/openwebtext, which is what the layer-6 GPT-2 SAE was trained on (confirmed from its config; 8M documents, ~24 GB, so always load with streaming=True). Backdoor data is built by script from this text; no special dataset is needed. Hard negatives come from a non-English Wikipedia sample and a small code dataset.

Pools

Shuffle once with a fixed seed, cut into non-overlapping pools, and save the assignment.

PoolUsed forContents
1 · PlantFine-tuning GPT-2 to create backdoorsFixed size; poisoned count set by the pilot calibration (trigger + target phrase)
2 · TrustedLearning "normal" (mean, covariance, SAE rarity stats)Clean only; a few thousand examples
2b · ValidationSetting thresholds for each modeClean only
3 · SAE fine-tuneConditions B / C / DMix set by condition; triggered sentences differ from the test pool's
4 · TestGrading, used onceNormal · hard negatives · triggered (a few hundred each)

Pipeline

  • Stream text with datasets (streaming mode).
  • Insert triggers with a seeded script; save which examples were changed.
  • Tokenize into chunks matching the SAE's context length; run the backdoored model; hook the SAE's layer; drop the BOS token.
  • Use an activation buffer (fill ~500k activations → shuffle → train → refill) instead of storing ~15 GB per condition.

Limitations to state

  • Models up to 2B; results may not hold at frontier scale.
  • GPT-2 and Gemma differ in architecture, training data and SAE type as well as size, so a GPT-2 vs. Gemma difference isn't purely a size effect (the Pythia ladder isolates size for raw detection only).
  • Planted, simple triggers; real attackers can adapt (see the obfuscated-activations work).
  • Fixed-phrase behavior is easier to detect than subtle behaviors.
